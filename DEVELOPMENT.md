## Working safely

Follow [INSTALLATION.md](INSTALLATION.md), reuse an existing Python 3.12 `.venv`, and preserve private `.env` contents. Do not commit generated storage, uploaded files, tokens, provider keys, local reports or private reference PDFs. Use synthetic datasets for tests and examples.

The current integration divides responsibilities among API/store/jobs, deterministic engines, optional AI and browser UI. [docs/API_CONTRACT.md](docs/API_CONTRACT.md) is the shared request/response and module interface. Coordinate contract changes before changing both ends. Do not assume another component is finished merely because its import or route exists.

## Build and run

```bash
source .venv/bin/activate
npm ci
npm run build
uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

The existing build script runs Tailwind into `frontend/styles.css` and `frontend/build.mjs` copies ECharts and its license into `frontend/vendor/`. Do not remove dependency notices. No Node server or CDN is needed at runtime. Development reload may be used locally, but interrupts jobs; never add multiple workers.

## Validation commands

These commands are **not a claim that checks passed**. Run the smallest relevant set after dependencies and component files exist:

```bash
source .venv/bin/activate
python -m pytest tests/test_store.py tests/test_api.py -q
python -m pytest tests/test_ai.py -q
python -m ruff check backend tests
npm run check
npm run build
```

For the complete available Python suite and browser integration:

```bash
python -m pytest -q
npm run install:browser
npm run test:browser
```

`npm run install:browser` installs Chromium using the project's helper into `node_modules/.cache/ms-playwright`; the Playwright configuration defaults to that same browser location and avoids system temporary directories. Browser setup may require system libraries; inspect the project Playwright configuration for its server command/port and base URL. `npm run check` includes the browser configuration/spec syntax and will fail while those files are still being implemented. Browser tests require built local assets. Do not run overlapping servers on the same port or infer browser success from JavaScript syntax checks.

To generate browser screenshots from the bundled synthetic Quality Issues sample:

```bash
UPDATE_SCREENSHOTS=1 npm run test:browser
```

The frontend implementer verified this workflow and generated six actual screenshots from the bundled synthetic Quality Issues sample: `docs/screenshots/{dashboard-dark,dashboard-light,column-profiler,mobile-overview,quality-lab,cleaning-studio}.png`. These are local test-run artifacts, not deployment screenshots. Never substitute private uploaded data.

To use an already-running local API instead of the test-managed server:

```bash
PLAYWRIGHT_BASE_URL=http://127.0.0.1:8000 npm run test:browser
```

For environments that require all scratch/test artifacts to stay in the repository, select an explicit base directory rather than a system temporary directory:

```bash
mkdir -p .work/test-scratch
TMPDIR="$PWD/.work/test-scratch" python -m pytest --basetemp="$PWD/.work/pytest" -q
```

Pytest recreates the specified base directory: dedicate it to disposable test files only. Remove only artifacts created for your run; never recursively remove an existing dataset store or another worker's environment.

## Required evidence before release

Keep exact commands, environment, exit status and observed failures in [docs/VALIDATION.md](docs/VALIDATION.md), which the parent is updating with final backend/browser evidence and completed bounded security reviews. Distinguish unit tests, API tests, browser checks, image builds and a real deployed smoke test. Do not invent screenshots, latency, memory usage, dataset sizes tested or success counts.

Important cases include:

- Separate dataset tokens; no unauthenticated access or token-in-URL downloads.
- Malformed/oversized input, row/column/expansion limits and ambiguous import choices.
- CSV unquoted blanks versus quoted empty strings, literal null-like tokens, leading-zero IDs, escaped quotes and multiline fields; include the engine's 2,000-row/20-null pandas-to-CSV regression and `QUOTE_NOTNULL` export/reingestion checks.
- Cooperative timeout with a still-running thread, slot retention and no timed-out baseline publication.
- Stale preview/revision rejection, branching parent pointers and restore after undo plus apply.
- Cached profile reuse and stable internal IDs across transformations.
- Formula-like cells and headers, escaped HTML, and clearly unsupported SQL operations.
- AI disabled/unavailable paths, aggregate-only payloads and no secret disclosure.
- Expiry/deletion, missing assets, busy/capacity states and keyboard-accessible browser behavior.

## Dependency/release discipline

Keep `requirements.txt` and the release lock synchronized through the project's chosen lock-generation process; the Dockerfile requires the exact filename `requirements.lock.txt`. Validate the resolved packages under Python 3.12. Regenerate npm's lock when changing manifests and use `npm ci` to check reproducibility. Neither floating base-image tags nor a requirements file without hashes provides a complete supply-chain attestation.
